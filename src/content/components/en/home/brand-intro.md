heading: Good technology starts with good listening.
body:
  - Before a single line of code is written, EMVEE first tries to understand the real problem.
  - "Who uses the solution? What organisation is behind it? And what actually needs to be simpler, rather than more elaborate?"
  - Sometimes that also means not building something. A feature nobody needs adds no value, only upkeep.
  - That requires listening before designing, and designing before building. Not because it is slower, but because it prevents unnecessary changes later on.
